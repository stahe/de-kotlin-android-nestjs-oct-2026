    5. Kapitel 4 - Der Kotlin-Client für die Anwendung RdvMedecins

    5.1. Überblick über die Architektur

    Dieser Client kommuniziert mit dem Server [rdvmedecins-nestjs-server] des Kurses – der völlig unverändert bleibt – über dieselben Routen: HTTP (POST [/login], GET [/getAllDoctors], GET [/getAllClients], GET [/getDoctorScheduleOfDay/:doctorId/:day], POST [/addAppointment], POST [/deleteAppointment]), mit demselben JSON-Umschlag [{ status, data }] und derselben Token-Authentifizierung [JWT] (Header [Authorization: Bearer <token>]).

// RdvMedecinsApplication.kt
// -------------------------------------------------------------------------
// Erste Hälfte der lib/main.dart der Flutter-Version: Aufbau der Services der
// Anwendung, GENAU EINMAL.
//
// Warum eine Application-Klasse? Unter Android wird der Bildschirm (die Activity, siehe
// MainActivity) bei jeder Drehung des Smartphones, bei jedem Wechsel der
// Systemsprache usw. ZERSTÖRT und anschließend NEU ERSTELLT. In der
// Activity aufgebaute Services würden daher bei jeder Drehung neu aufgebaut. Das
// Application-Objekt hingegen wird beim Start des Prozesses erzeugt
// und lebt so lange wie dieser: Es ist der richtige Ort für Objekte, die
// während der gesamten Lebensdauer der Anwendung bestehen müssen. Es wird in
// AndroidManifest.xml deklariert (Attribut android:name des Tags <application>).
//
// Die REIHENFOLGE beim Aufbau ist wichtig, wie in der Flutter-Version:
// AuthService benötigt SettingsService (die Server-URL); der authentifizierte
// HTTP-Client benötigt AuthService (das Token); AppointmentService benötigt
// den authentifizierten HTTP-Client und SettingsService.
// =========================================================================

package fr.rdvmedecins.client

import android.app.Application
import android.content.Context
import fr.rdvmedecins.client.core.http.AuthInterceptor
import fr.rdvmedecins.client.core.i18n.TranslationsService
import fr.rdvmedecins.client.core.services.AuthService
import fr.rdvmedecins.client.core.services.AppointmentService
import fr.rdvmedecins.client.core.services.SettingsService
import okhttp3.OkHttpClient
import java.util.concurrent.TimeUnit

class RdvMedecinsApplication : Application() {

    // lateinit: Diese Properties ohne Null-Wert werden in
    // onCreate() initialisiert und nicht im Konstruktor (siehe den Kotlin-Kurs)
    lateinit var settings: SettingsService
        private set
    lateinit var auth: AuthService
        private set
    lateinit var api: AppointmentService
        private set
    lateinit var translations: TranslationsService
        private set

    // wird von Android beim Start der Anwendung aufgerufen, vor jedem Bildschirm
    override fun onCreate() {
        super.onCreate()

        // die Einstellungen der Anwendung: eine kleine private Schlüssel-Wert-Datei,
        // die das Beenden der Anwendung überdauert - das Pendant zum
        // localStorage eines Browsers
        val prefs = getSharedPreferences("rdvmedecins", Context.MODE_PRIVATE)

        // 1. zuerst SettingsService: die anderen benötigen ihn
        settings = SettingsService(prefs)

        // 2. ein "einfacher" OkHttp-HTTP-Client, den AuthService für
        //    POST /login verwendet. Kurze Timeouts: Auf Mobilgeräten ist eine schnelle Fehlermeldung
        //    besser als endloses Warten, wenn der Server
        //    nicht erreichbar ist (falsche URL, WLAN aus...).
        val plainHttp = OkHttpClient.Builder()
            .connectTimeout(10, TimeUnit.SECONDS)

    var clients by mutableStateOf<List<Client>>(emptyList())
        private set
    var schedule by mutableStateOf<DoctorDaySchedule?>(null)
        private set
    var error by mutableStateOf<String?>(null)
        private set

    // ist geöffnet (siehe App.kt und BookingDialog.kt)

    // einer Buchung oder Stornierung zu aktualisieren. Wird nie angezeigt: Einfache
    // Properties genügen, sie müssen keine Compose-Zustände sein.
    private var lastDoctorId: Int? = null
    private var lastDay: String? = null

        // FLOW von Werten: Er liefert sofort den aktuellen Wert von auth.isLoggedIn,

        // dem "watch(() => auth.isLoggedIn, ..., { immediate: true })" von Vue.js
        // - und dem Abonnement per addListener(...) samt anfänglichem Aufruf,
        // das die Flutter-Version von Hand schreiben musste.

        // automatisch abgebrochen, wenn das ViewModel zerstört wird (das removeListener(...)
        // aus dispose() auf Flutter-Seite ist nicht mehr nötig).
        viewModelScope.launch {
            snapshotFlow { auth.isLoggedIn }.collect { loggedIn ->
                if (loggedIn) {
                    loadInitialLists()
                } else {
                    reset()

        }
    }

    // laden die Ärzte und die Patienten ein für alle Mal. Zwei
    // getrennte Coroutinen: Die beiden Anfragen werden PARALLEL gesendet.
    // -----------------------------------------------------------------------
    private fun loadInitialLists() {
        runSafely { doctors = api.getAllDoctors() }
        runSafely { clients = api.getAllClients() }

    // -----------------------------------------------------------------------
    // bei der Abmeldung (Button oder vom Server abgelehntes Token): Wir
    // verwerfen den fachlichen Zustand, damit ein neuer Benutzer nicht, auch nicht für einen
    // Augenblick, den Terminkalender des vorherigen Benutzers sieht
    // -----------------------------------------------------------------------
    private fun reset() {
        doctors = emptyList()
        clients = emptyList()
        schedule = null
        error = null
        slotBeingBooked = null
        lastDoctorId = null
        lastDay = null
    }

    // Button "Log out": Es genügt, AuthService abzumelden -
    // snapshotFlow (siehe init) löst dann reset() aus
    fun logOut() {
        auth.logOut()
    }

    // -----------------------------------------------------------------------
    // Button "View schedule" von DoctorDayPicker
    // -----------------------------------------------------------------------
    fun searchSchedule(doctorId: Int, day: String) {
        error = null
        lastDoctorId = doctorId
        lastDay = day
        loadSchedule()

    // Dialog und merken uns das betreffende Zeitfenster. Mit Compose ist ein Dialog
    // Teil der Anzeige wie alles andere: Er wird

        slotBeingBooked = null

    // Button "Confirm" des Dialogs
    fun confirmBooking(clientId: Int) {
        val slot = slotBeingBooked ?: return
        val day = lastDay ?: return
        slotBeingBooked = null // schließt den Dialog
        runSafely {
            api.addAppointment(day, clientId, slot.id)
            loadSchedule() // das Zeitfenster erscheint nun als belegt
        }
    }

    // -----------------------------------------------------------------------
    // Button "Cancel" eines belegten Zeitfensters in ScheduleView
    // -----------------------------------------------------------------------
    fun cancelAppointment(appointment: AppointmentJson) {
        runSafely {
            api.deleteAppointment(appointment.id)
            loadSchedule() // das Zeitfenster wird wieder frei
        }
    }

    private fun loadSchedule() {
        val doctorId = lastDoctorId ?: return
        val day = lastDay ?: return
        runSafely { schedule = api.getDoctorScheduleOfDay(doctorId, day) }
    }

    // -----------------------------------------------------------------------
    // führt [action] in einer ViewModel-Coroutine aus und wandelt jede
    // Exception in eine auf dem Bildschirm angezeigte Fehlermeldung um. Das Auslagern
    // dieses try/catch erspart es, ihn in jeder obigen Methode zu wiederholen.
    // Eine CancellationException ist KEIN Fehler: Sie ist das Abbruchsignal
    // einer Coroutine (ViewModel zerstört) und muss
    // weitergereicht werden.
    // -----------------------------------------------------------------------
    private fun runSafely(action: suspend () -> Unit) {
        viewModelScope.launch {
            try {
                action()
            } catch (e: CancellationException) {
                throw e
            } catch (e: Exception) {
                Log.w("RdvMedecins", "a server call failed", e) // siehe Logcat
                error = e.message ?: e.toString()
            }
        }
    }
}

// (List<String>), wo bei Erfolg zum Beispiel ein Terminkalender erwartet wird.

package fr.rdvmedecins.client.core.models

import kotlinx.serialization.DeserializationStrategy
import kotlinx.serialization.json.Json
import kotlinx.serialization.json.JsonNull
import kotlinx.serialization.json.int
import kotlinx.serialization.json.jsonObject
import kotlinx.serialization.json.jsonPrimitive

// die JSON-Konfiguration, die vom gesamten Client gemeinsam genutzt wird:
// - ignoreUnknownKeys: Der Server sendet Felder, die dieser Client
//   nicht verwendet (z. B. die "version" eines Arztes) - wir ignorieren sie, statt
//   eine Exception auszulösen;
// - explicitNulls = false: Beim Kodieren wird eine null-Property nicht
//   geschrieben (ohne Auswirkung auf die Klassen dieses Clients, aber näher am
//   Verhalten von JSON.stringify auf JavaScript-Seite).
val ApiJson = Json {
    ignoreUnknownKeys = true
    explicitNulls = false
}

// Exception, die ausgelöst wird, wenn der Server mit einem fachlichen Status ungleich 0 antwortet
// (Ressource nicht gefunden, ungültiges Datum, Serverfehler)
class ResponseException(val status: Int) :
    Exception("The server responded with error status $status")

// dekodiert den Body einer {status, data}-Antwort und liefert "data" im
// durch [deserializer] beschriebenen Typ T (z. B. Doctor.serializer() oder
// ListSerializer(Doctor.serializer()) für eine Liste von Ärzten)
fun <T> decodeResponse(body: String, deserializer: DeserializationStrategy<T>): T {
    // 1. der Umschlag als generischer JSON-Baum
    val envelope = ApiJson.parseToJsonElement(body).jsonObject
    // 2. der fachliche Status
    val status = envelope.getValue("status").jsonPrimitive.int
    if (status != 0) {
        throw ResponseException(status)
    }
    // 3. "data", erst jetzt in den erwarteten Typ dekodiert
    val data = envelope["data"] ?: JsonNull
    return ApiJson.decodeFromJsonElement(deserializer, data)
}

import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableStateOf

import okhttp3.Request
import okhttp3.RequestBody.Companion.toRequestBody
import java.io.IOException

class AuthService(
    private val settings: SettingsService,
    private val prefs: SharedPreferences,
    // ein HTTP-Client OHNE den Authentifizierungs-Interceptor: POST /login
    // ist die einzige öffentliche Route des Servers, es gibt kein Token,
    // das gesendet werden könnte (siehe RdvMedecinsApplication)
    private val http: OkHttpClient,
) {
    // ––– Sitzungszustand, von der UI beobachtet –––
    var isLoggedIn by mutableStateOf(false)
        private set
    var login by mutableStateOf<String?>(null)
        private set
    var name by mutableStateOf<String?>(null)
        private set
    var role by mutableStateOf<Role?>(null)
        private set

    // das Token wird nie ANGEZEIGT: Es muss kein Compose-Zustand sein.
    // Es wird jedoch von AuthInterceptor auf einem Netzwerk-Thread gelesen:
    // @Volatile garantiert, dass dieser Thread immer den letzten vom
    // Main-Thread geschriebenen Wert sieht.
    @Volatile
    var accessToken: String? = null
        private set

    // berechnete Property: liest role bei jedem Zugriff neu (und abonniert bei einem Lesen während der
    // Anzeige die Anzeige auf Änderungen von role)
    val isAdmin: Boolean
        get() = role == Role.ADMIN

    init {
        restoreSession()
    }

    // -----------------------------------------------------------------------
    // liest eine möglicherweise bei einem früheren Start gespeicherte Sitzung neu
    // -----------------------------------------------------------------------
    private fun restoreSession() {
        val raw = prefs.getString(SESSION_KEY, null) ?: return // keine gespeicherte Sitzung
        try {
            // die Sitzung wurde als LoginResult gespeichert,
            // als JSON serialisiert (siehe logIn): Wir lesen sie unverändert zurück
            applySession(ApiJson.decodeFromString(LoginResult.serializer(), raw))
        } catch (e: Exception) {
            // unlesbarer Inhalt (z. B. das Format einer alten Version der
            // Anwendung): Wir verwerfen ihn, der Benutzer meldet sich erneut an
            prefs.edit { remove(SESSION_KEY) }
        }
    }

    // -----------------------------------------------------------------------
    // POST /login. "suspend": Diese Funktion kann so lange pausieren,
    // wie der Server für die Antwort braucht, OHNE den aufrufenden Thread zu blockieren -
    // das Pendant zu einer async-Funktion, die ein Future<LoginResult>
    // zurückgibt, auf Dart-Seite. Sie löst eine Exception aus, wenn die Anmeldung fehlschlägt.
    // -----------------------------------------------------------------------
    suspend fun logIn(login: String, password: String): LoginResult {
        // withContext(Dispatchers.IO): Der Block läuft auf einem für Ein-/Ausgabe
        // reservierten Thread. Android VERBIETET jeden Netzwerkzugriff
        // vom Main-Thread aus (NetworkOnMainThreadException): Er
        // zeichnet die UI und darf nie warten.
        val result = withContext(Dispatchers.IO) {
            val body = ApiJson.encodeToString(LoginRequest.serializer(), LoginRequest(login, password))
            val request = Request.Builder()
                .url("${settings.apiBaseUrl}/login")
                .post(body.toRequestBody(JSON_TYPE))
                .build()
            // execute(): ein BLOCKIERENDER Aufruf - hier harmlos, wir sind auf einem
            // Ein-/Ausgabe-Thread. use { } schließt die Antwort am Ende des
            // Blocks, was auch passiert (das Pendant zum
            // try-with-resources von Java, siehe den Kotlin-Kurs).
            http.newCall(request).execute().use { response ->
                // falsche Zugangsdaten: Der Server antwortet 401 Unauthorized
                if (!response.isSuccessful) {
                    throw IOException("Login failed (HTTP ${response.code})")
                }
                decodeResponse(response.body!!.string(), LoginResult.serializer())
            }
        }
        // zurück auf dem Thread des Aufrufers (dem Main-Thread):
        // Hier, und nicht auf dem Ein-/Ausgabe-Thread, ändern wir den
        // von der UI beobachteten Zustand
        applySession(result)
        prefs.edit { putString(SESSION_KEY, ApiJson.encodeToString(LoginResult.serializer(), result)) }
        return result
    }

    // -----------------------------------------------------------------------
    // Abmeldung: Wir verwerfen die Sitzung, im Speicher und in den Einstellungen.
    // Muss auf dem Main-Thread aufgerufen werden (siehe AuthInterceptor).
    // -----------------------------------------------------------------------
    fun logOut() {
        accessToken = null
        login = null
        name = null
        role = null
        isLoggedIn = false
        prefs.edit { remove(SESSION_KEY) }
    }

    private fun applySession(session: LoginResult) {
        accessToken = session.accessToken
        login = session.login
        name = session.name
        role = session.role
        isLoggedIn = true
    }

    companion object {
        private const val SESSION_KEY = "rdvmedecins.session"
        private val JSON_TYPE = "application/json; charset=utf-8".toMediaType()
    }
}

package fr.rdvmedecins.client.core.http

import android.os.Handler
import android.os.Looper

import okhttp3.Interceptor
import okhttp3.Response

class AuthInterceptor(private val auth: AuthService) : Interceptor {

    // ein an den Main-Thread gebundener Handler: Damit können wir ihm Arbeit
    // von einem anderen Thread übergeben (siehe intercept weiter unten)
    private val mainThread = Handler(Looper.getMainLooper())

    // wird von OkHttp für JEDE Anfrage auf einem Netzwerk-Thread aufgerufen
    override fun intercept(chain: Interceptor.Chain): Response {
        // 1. die ursprüngliche Anfrage, plus das Token, falls vorhanden. Eine
        //    OkHttp-Anfrage ist unveränderlich: newBuilder() erstellt eine
        //    veränderbare Kopie davon.
        val token = auth.accessToken
        val request = if (token == null) {
            chain.request()
        } else {
            chain.request().newBuilder()
                .header("Authorization", "Bearer $token")
                .build()
        }
        // 2. wir lassen die Anfrage ihren Weg zum Server fortsetzen
        val response = chain.proceed(request)
        // 3. Token abgelehnt: Wir melden den Benutzer ab. Diese Methode
        //    läuft auf einem Netzwerk-Thread; logOut() ändert jedoch
        //    den von der UI angezeigten Zustand: Daher übergeben wir diesen Aufruf an den
        //    Main-Thread (post), ohne auf seine Ausführung zu warten - das
        //    Gegenstück zum unawaited(auth.logOut()) der Flutter-Version.
        if (response.code == 401) {
            mainThread.post { auth.logOut() }
        }
        return response
    }
}

    Kommentieren wir diesen Code:

    • Zeile 26: Die Klasse implementiert die Schnittstelle [okhttp3.Interceptor]. OkHttp leitet jede Anfrage vor dem Senden und jede Antwort vor der Rückgabe an den Aufrufer durch die Interceptoren des Clients: Das ist das Konzept der HTTP-Interceptoren von Angular. Die Flutter-Version, der ein solcher Mechanismus im Paket [http] fehlt, kapselte den HTTP-Client in einer eigenen Klasse;
    • Zeile 30: ein [Handler] , der dem Haupt-Thread zugeordnet ist ([Looper.getMainLooper()]): Damit lässt sich Arbeit aus einem anderen Thread an ihn delegieren;
    • Zeilen 41–43: Eine OkHttp-Anfrage ist UNVERÄNDERLICH; [newBuilder()] erstellt eine veränderbare Kopie davon, ergänzt um den Header [Authorization];
    • Zeile 46: [chain.proceed(request)] – die Anfrage wird zum Server weitergeleitet; die Methode gibt die Antwort zurück;
    • Zeilen 52–53: Token abgelehnt (401): [intercept] läuft in einem Netzwerk-Thread, aber [logOut()] ändert den angezeigten Zustand. Der Aufruf wird daher an den Haupt-Thread delegiert ([post { ... }]), ohne auf seine Ausführung zu warten – das Pendant zu [unawaited(auth.logOut())] in der Flutter-Version.

// Port der lib/core/i18n/translations_service.dart: Umschalten der UI zwischen
// Französisch und Englisch, im laufenden Betrieb, ohne Neustart der
// Anwendung. Die Wörterbücher sind DIESELBEN JSON-Dateien wie die

// in app/src/main/assets/i18n/: Der Ordner assets/ eines Android-Projekts wird
// unverändert in die Anwendung (die .apk-Datei) eingebettet, wie die
// in der pubspec.yaml der Flutter-Version deklarierten Assets.
//

// Anwendung beruht auf den Ressourcendateien res/values/strings.xml
// (Englisch) und res/values-fr/strings.xml (Französisch), wobei das System
// die passende Datei anhand der Sprache des SMARTPHONES wählt. Dieses Dokument
// behält die von allen Varianten des Kurses gemeinsam genutzten JSON-Wörterbücher
// und den FR/EN-Umschalter innerhalb der Anwendung selbst bei, wie
// die ursprüngliche Anwendung (2014).

package fr.rdvmedecins.client.core.i18n

import android.content.SharedPreferences
import android.content.res.AssetManager
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableStateOf
import androidx.compose.runtime.setValue
import androidx.core.content.edit
import fr.rdvmedecins.client.core.models.ApiJson
import kotlinx.serialization.json.JsonElement
import kotlinx.serialization.json.JsonObject
import kotlinx.serialization.json.JsonPrimitive
import kotlinx.serialization.json.jsonObject

class TranslationsService(
    private val assets: AssetManager,
    private val prefs: SharedPreferences,
) {
    // die angezeigte Sprache: ein Compose-Zustand. Da t(...) weiter unten
    // diese Property LIEST, wird jeder mit t(...) angezeigte Text bei einem Sprachwechsel automatisch
    // neu angezeigt - anders als in der Flutter-Version muss kein context.watch<...>()
    // geschrieben werden.
    var currentLanguage by mutableStateOf(prefs.getString(LANGUAGE_KEY, null) ?: DEFAULT_LANGUAGE)
        private set

    // die bereits geladenen Wörterbücher, nach Sprache ("fr" -> {...})
    private val dictionaries = mutableMapOf<String, JsonObject>()

    fun changeLanguage(language: String) {
        if (language == currentLanguage) {
            return
        }
        dictionary(language) // lädt das Wörterbuch, BEVOR die Sprache geändert wird
        currentLanguage = language
        prefs.edit { putString(LANGUAGE_KEY, language) }
    }

    // -----------------------------------------------------------------------
    // t("LOGIN.TITLE"): durchläuft das Wörterbuch der aktuellen Sprache
    // Segment für Segment ("LOGIN", dann "TITLE"). Wird der Schlüssel
    // nicht gefunden, wird der Schlüssel selbst zurückgegeben: Der fehlende Text bleibt so
    // auf dem Bildschirm sichtbar, ohne die Anwendung abstürzen zu lassen.
    // -----------------------------------------------------------------------
    fun t(key: String): String {
        var currentValue: JsonElement = dictionary(currentLanguage)
        for (segment in key.split('.')) {
            currentValue = (currentValue as? JsonObject)?.get(segment) ?: return key
        }
        val primitive = currentValue as? JsonPrimitive
        return if (primitive != null && primitive.isString) primitive.content else key
    }

    // -----------------------------------------------------------------------
    // das Wörterbuch einer Sprache, beim ersten Bedarf geladen und dann im
    // Speicher gehalten. getOrPut: gibt den dem Schlüssel zugeordneten Wert zurück oder führt
    // den Block aus, speichert dessen Ergebnis und gibt es zurück. Das Lesen ist
    // synchron: Die beiden Dateien sind nur einige hundert
    // Bytes groß, ihr Lesen erfolgt augenblicklich.
    // -----------------------------------------------------------------------
    private fun dictionary(language: String): JsonObject =
        dictionaries.getOrPut(language) {
            assets.open("i18n/$language.json").bufferedReader().use { reader ->
                ApiJson.parseToJsonElement(reader.readText()).jsonObject
            }
        }

    companion object {
        private const val LANGUAGE_KEY = "rdvmedecins.language"
        private val DEFAULT_LANGUAGE = if (java.util.Locale.getDefault().language == "fr") "fr" else "en"
    }
}

    Kommentieren wir diesen Code:

    • Zeilen 43–44: [currentLanguage] – ein beobachtbarer Zustand. Da [t(...)] diese Eigenschaft LIEST, wird jede @Composable-Funktion, die Text mit [t(...)] anzeigt, bei einem Sprachwechsel automatisch neu zusammengesetzt: Es muss kein [context.watch<...>()] geschrieben werden;
    • Zeilen 49–55: [changeLanguage(...)] – lädt das Wörterbuch, BEVOR die Sprache umgeschaltet wird, und speichert dann die Auswahl in den Einstellungen;
    • Zeilen 64–70: [t("LOGIN.TITLE")] – durchläuft das Wörterbuch Segment für Segment. [as?] ist die „sichere“ Typumwandlung von Kotlin: Sie liefert [null] (statt eine Ausnahme auszulösen), wenn das Objekt nicht den verlangten Typ hat; in Kombination mit [?: return key] führt das dazu, dass der Schlüssel selbst zurückgegeben wird, sobald ein Segment nicht gefunden wird – der fehlende Text bleibt auf dem Bildschirm sichtbar;

// die ExposedDropdownMenu*-APIs sind in Material 3 noch als "experimental" markiert:
// @OptIn legt fest, dass wir sie bewusst verwenden
@OptIn(ExperimentalMaterial3Api::class)
@Composable
fun <T> DropdownList(
    label: String,
    placeholder: String,     // Text, der angezeigt wird, solange nichts ausgewählt ist
    items: List<T>,
    selectedId: Int?,        // id des ausgewählten Elements oder null
    idOf: (T) -> Int,
    itemLabel: (T) -> String,
    onSelect: (Int) -> Unit,
    modifier: Modifier = Modifier,
) {
    // Menü geöffnet oder geschlossen: ein LOKALER Zustand dieser Funktion, der von einer Anzeige zur nächsten
    // durch remember gemerkt wird (siehe Kapitel 3)
    var menuOpen by remember { mutableStateOf(false) }
    val selected = items.firstOrNull { idOf(it) == selectedId }

    ExposedDropdownMenuBox(
        expanded = menuOpen,
        onExpandedChange = { menuOpen = it },
        modifier = modifier,
    ) {
        // das Feld, das die aktuelle Auswahl anzeigt; menuAnchor(...) macht es zum
        // Ankerpunkt des Menüs (ein Klick darauf öffnet das Menü)
        OutlinedTextField(
            value = selected?.let(itemLabel) ?: "",
            onValueChange = {},
            readOnly = true,
            singleLine = true,
            label = { Text(label) },
            placeholder = { Text(placeholder) },
            trailingIcon = { ExposedDropdownMenuDefaults.TrailingIcon(expanded = menuOpen) },
            modifier = Modifier
                .menuAnchor(ExposedDropdownMenuAnchorType.PrimaryNotEditable)
                .fillMaxWidth(),
        )

        ExposedDropdownMenu(expanded = menuOpen, onDismissRequest = { menuOpen = false }) {
            items.forEach { item ->
                DropdownMenuItem(
                    text = { Text(itemLabel(item)) },
                    onClick = {
                        onSelect(idOf(item))
                        menuOpen = false
                    },
                )
            }
        }
    }
}

@Composable
fun BookingDialog(
    slot: SlotJson,
    clients: List<Client>,
    onConfirm: (clientId: Int) -> Unit,
    onClose: () -> Unit,
) {
    val t = LocalTranslations.current::t
    // der ausgewählte Patient (seine id) oder null, solange keiner ausgewählt ist
    var clientId by rememberSaveable { mutableStateOf<Int?>(null) }

    AlertDialog(
        // Tippen außerhalb des Dialogs oder die "Zurück"-Taste des Smartphones
        onDismissRequest = onClose,
        title = { Text(t("BOOKING_DIALOG.TITLE")) },
        text = {
            Column(verticalArrangement = Arrangement.spacedBy(16.dp)) {
                Text(
                    "${t("BOOKING_DIALOG.SLOT_FROM")} ${slot.startHour}:${slot.startMinute.toString().padStart(2, '0')} " +
                        "${t("BOOKING_DIALOG.SLOT_TO")} ${slot.endHour}:${slot.endMinute.toString().padStart(2, '0')}",
                )
                DropdownList(
                    label = t("BOOKING_DIALOG.PATIENT_LABEL"),
                    placeholder = t("BOOKING_DIALOG.CHOOSE_PATIENT"),
                    items = clients,
                    selectedId = clientId,
                    idOf = { it.id },
                    itemLabel = { "${it.title} ${it.firstName} ${it.lastName}" },
                    onSelect = { clientId = it },
                    modifier = Modifier.fillMaxWidth(),
                )
            }
        },
        // "Confirm": deaktiviert, solange kein Patient ausgewählt ist
        confirmButton = {
            Button(
                enabled = clientId != null,
                onClick = { clientId?.let(onConfirm) },
            ) { Text(t("BOOKING_DIALOG.CONFIRM")) }
        },
        dismissButton = {
            TextButton(onClick = onClose) { Text(t("BOOKING_DIALOG.CANCEL")) }
        },
    )
}

    Kommentieren wir diesen Code:

    • Zeilen 8–15: Der Kopfkommentar fasst den strukturellen Unterschied zur Flutter-Version zusammen. Flutter ÖFFNETE das Dialogfeld mit [showDialog(...)] und WARTETE auf sein Ergebnis (ein [Future<int?>]). In Compose ist ein Dialogfeld ein Oberflächenelement wie jedes andere: Es bleibt angezeigt, solange die Funktion, die es aufruft, es weiter aufruft. Es „gibt“ nichts „zurück“: Es meldet die Auswahl über zwei Funktionen, [onConfirm] und [onClose] – genau die beiden Ereignisse [confirm] / [close] der Komponente [BookingDialog.vue] in der Vue.js-Variante;
    • Zeile 48: der gewählte Patient: [rememberSaveable]; der Patient bleibt auch nach einer Drehung des Bildschirms bei geöffnetem Dialogfeld ausgewählt;
    • Zeilen 50–52: [AlertDialog(...)] – das Dialogfeld von Material 3 mit Titel, Inhalt ([text]) und zwei Buttons. [onDismissRequest] wird aufgerufen, wenn der Benutzer außerhalb des Dialogfelds tippt oder die „Zurück“-Taste des Smartphones drückt;
    • Zeilen 73–76: der Button „Bestätigen“, der deaktiviert ist, bis ein Patient ausgewählt wurde. [clientId?.let(onConfirm)]: Wenn [clientId] nicht [null] ist, wird [onConfirm] aufgerufen – mit dessen Wert.

    Nach der Anmeldung mit [admin]/[admin] weicht der Anmeldebildschirm der Auswahl von Arzt und Tag; die Titelleiste zeigt das Rollen-Badge und den Abmelde-Button. Im Hintergrund hat [AppViewModel] die Ärzte und Patienten geladen:
